# 用Agent Skills装备现实世界的代理

> 来源: https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills
> 发布日期: 2025年10月16日

随着AI代理（AI agents）承担越来越复杂的现实世界任务，它们需要结构化的方式来获取和应用特定领域的知识。这促使我们创建了**Agent Skills**：由指令、脚本和资源组成的有组织的文件夹，代理可以动态发现和加载这些文件夹，从而更好地执行特定任务。

在这篇文章中，我们将解释什么是Skills，展示它们如何工作，并分享构建你自己的Skills的最佳实践。

**更新**：Agent Skills已作为开放标准发布，支持跨平台可移植性。

## 什么是Skill？

最简单地说，一个skill就是一个包含**SKILL.md**文件的目录。该文件描述了skill的用途，为代理提供指令，并可选地引用其他资源，如脚本、模板和配置文件。

Skills通过系统提示（system prompt）在上下文窗口（context window）中被触发。当代理遇到与某个skill描述相匹配的任务时，它会将该skill的指令和资源加载到其工作上下文中。

```
my-skill/
├── SKILL.md          # 核心指令和元数据
├── scripts/          # 辅助脚本
├── templates/        # 输出模板
└── resources/        # 参考资料
```

## 渐进式披露（Progressive Disclosure）

**渐进式披露（Progressive disclosure）**是使Agent Skills灵活且可扩展的核心设计原则。就像一本组织良好的手册一样，skills让Claude仅在需要时加载信息。

渐进式披露不是将所有可能的指令塞入单个提示中，而是允许代理：
1. 根据当前任务发现可用的skills
2. 仅加载相关skill的指令
3. 根据需要深入子资源

这种方法在提供深度领域知识访问的同时，保持上下文窗口的高效使用。

## 构建有效的Skills

### 从评估开始

在构建skill之前，先定义如何衡量其有效性。创建代表该skill应处理的任务的测试用例，并建立没有该skill时的基准性能。

### 为规模化而构建结构

当SKILL.md文件变得难以管理时，将内容拆分为单独的文件并引用它们。如果某些上下文是互斥的或很少一起使用，保持路径分离可以减少token使用量。

### 从Claude的视角思考

编写指令时就像你在为新团队成员做入职培训一样。将隐含知识显式化。包括：
- 决策背后的"为什么"，而不仅仅是"做什么"
- 常见陷阱及如何避免
- 处理模糊情况的决策树
- 好的和差的输出示例

### 对确定性任务使用脚本

对于需要精确执行的任务（如运行特定命令、解析结构化数据或应用格式化规则），应包含脚本，而不是依赖代理每次自己摸索步骤。

## Skill组合（Skill Composition）

现在，任何人都可以通过捕获和分享程序性知识，用可组合的能力来专门化他们的代理，而不是为每个用例构建碎片化的、定制设计的代理。Skills可以引用其他skills，创建可组合的能力层。

## 最佳实践

1. **保持SKILL.md的专注**：一个skill应该针对一个领域或工作流
2. **对skills进行版本控制**：在迭代过程中跟踪变更
3. **用真实任务测试**：不要只测试理想路径——要包含边界情况
4. **记录假设条件**：为代理明确上下文
5. **使用渐进式披露**：不要一开始就加载所有内容——让代理根据需要逐步深入

## 结论

Agent Skills代表了从单体提示（monolithic prompts）到模块化、可组合能力的转变。通过将领域知识组织为可发现、可加载的单元，我们使代理能够有效地应对更广泛的现实世界任务。Skills现在已是一个开放标准——我们鼓励社区共同构建、分享和迭代skills。
