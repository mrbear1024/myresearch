# Claude Code 自动模式：一种更安全的跳过权限方式

> 来源：https://www.anthropic.com/engineering/claude-code-auto-mode
> 发布时间：2025年

自动模式（Auto mode）是 Claude Code 的一种新模式，它将审批委托给基于模型的分类器（model-based classifiers）——在手动审查和无防护措施之间取得平衡。

## 挑战

Claude Code 的权限系统确保了安全性，但频繁的提示会中断复杂的工作流。用户希望在不牺牲安全性的前提下获得更多自主权。问题在于：如何在保持安全的同时减少摩擦？

## 自动模式的工作原理

自动模式使用**两层防御**：一层负责 Claude 读取的内容，另一层负责 Claude 执行的操作。

### 输入层：提示注入检测（Prompt Injection Detection）

在输入层，一个服务端的提示注入探测器（prompt-injection probe）会在工具输出进入智能体上下文之前对其进行扫描。这能够捕获通过文件、网页或 API 响应中的恶意内容劫持智能体的企图。

如果探测器检测到潜在的注入，可疑内容会被标记，智能体会收到警告，使其能够谨慎地继续而不是盲目执行注入的指令。

### 输出层：对话记录分类（Transcript Classification）

在输出层，一个对话记录分类器（transcript classifier）在每个操作执行前对其进行评估。分类器会分析：
- 完整的对话上下文
- 拟执行的操作
- 该操作是否与用户的原始意图一致

看起来安全的操作会被自动批准。看起来有风险或与用户请求不一致的操作会被上报（escalated）进行人工审查。

## 自动模式中的权限规则

进入自动模式后，已知会授予任意代码执行权限的权限规则会被移除，包括：
- 全面的 shell 访问权限
- 通配符脚本解释器（`python`、`node`、`ruby` 及类似程序）
- 包管理器运行命令（package manager run commands）

这防止自动模式成为不受限制的代码执行载体，同时仍允许 Claude 自主执行大多数开发任务。

## 安全属性

自动模式维护几个关键的安全属性：
1. **意图对齐（Intent Alignment）**：操作必须与用户的请求一致
2. **注入抵抗（Injection Resistance）**：来自外部来源的内容在处理前会被扫描
3. **上报路径（Escalation Path）**：不确定的操作始终会上报给用户
4. **禁止任意执行（No Arbitrary Execution）**：即使在自动模式下，危险模式也会被阻止

## 成果

在测试中，自动模式：
- 显著减少了标准开发任务的权限提示
- 捕获了来自恶意文件内容的提示注入尝试
- 在对抗性基准测试（adversarial benchmarks）中保持了安全性
- 提升了长时间编码会话的用户生产力

## 何时使用自动模式

自动模式最适合：
- 包含大量文件编辑的长时间编码会话
- 在明确定义的项目边界内的任务
- 操作可预测的开发工作流

对于涉及敏感数据、生产环境部署或不熟悉的代码库的任务，仍然建议使用手动模式。
