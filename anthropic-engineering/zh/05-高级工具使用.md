# 介绍Claude开发者平台上的高级工具使用

> 来源: https://www.anthropic.com/engineering/advanced-tool-use
> 作者: Bin Wu
> 贡献者: Adam Jones, Artur Renault, Henry Tay, Jake Noble, Noah Picard, Sam Jiang 以及Claude开发者平台团队
> 发布时间: 2025年11月24日

要构建高效的代理（agents），它们需要能够使用无限的工具库，而无需将所有定义预先塞入上下文中。今天，我们发布了三个新的测试版功能，让Claude能够动态地发现、学习和执行工具。这些功能将工具使用从简单的函数调用（function calling）推向了智能编排（intelligent orchestration）。

随着代理处理越来越复杂的工作流程——涉及数十个工具和大型数据集——动态发现、高效执行和可靠调用变得至关重要。

## 挑战：工具扩展

仅工具定义就可能消耗大量的token预算。58个工具大约使用55K个token，我们曾见到工具定义在优化前消耗134K个token。随着工具数量的增长，预先加载所有定义的传统方法变得不可持续。

## 工具搜索工具（Tool Search Tool）

工具搜索工具（Tool Search Tool）不再预先加载所有工具定义，而是按需发现工具，因此Claude只会看到当前任务实际需要的工具。这实现了85%的token使用量减少，同时保持对完整工具库的访问。

工具搜索工具使Claude能够通过搜索访问数千个工具，而不会消耗其上下文窗口（context window）。当Claude需要某种能力时，它会搜索相关工具、检索其定义并使用它——所有这些都在一轮对话中完成。

**结果**：工具搜索工具保留了191,300个token的上下文，而Claude传统方法为122,800个。Opus 4从49%提升到74%，Opus 4.5在启用工具搜索工具后从79.5%提升到88.1%。

## 编程式工具调用（Programmatic Tool Calling）

编程式工具调用（Programmatic Tool Calling）使Claude能够通过代码来编排工具，而不是通过逐个的API往返调用。Claude不再逐个请求工具，而是编写代码来调用多个工具、处理其输出，并控制哪些信息实际进入其上下文窗口。

脚本在代码执行工具（Code Execution tool，一个沙盒环境）中运行，当需要来自你工具的结果时会暂停。每次API往返都需要模型推理。当Claude在单个代码块中编排20多个工具调用时，你可以消除19次以上的推理过程。

通过将中间结果排除在Claude的上下文之外，编程式工具调用显著减少了token消耗——在复杂研究任务中，平均使用量从43,588降至27,297个token，减少了37%。

## 工具使用示例（Tool Use Examples）

工具使用示例（Tool Use Examples）提供了一种通用标准，用于演示如何有效使用给定工具。通过提供正确工具使用模式的示例，可以减少参数错误和格式错误的调用。

示例作为少样本示范（few-shot demonstrations），帮助Claude理解：
- 预期的输入格式
- 常见的参数组合
- 典型的使用模式
- 需要处理的边界情况

## 入门指南

我们建议从你最大的瓶颈开始：
- **工具定义导致的上下文膨胀** → 工具搜索工具（Tool Search Tool）
- **大量中间结果污染上下文** → 编程式工具调用（Programmatic Tool Calling）
- **参数错误和格式错误的调用** → 工具使用示例（Tool Use Examples）

这三个功能协同工作，创建更高效、更可靠的工具使用体验。从一个功能开始，衡量其影响，然后根据需要逐步叠加其他功能。
