# 智能体编码基准中的基础设施噪声（Infrastructure Noise）

> 来源：https://www.anthropic.com/engineering/infrastructure-noise
> 发布时间：2025年

基础设施配置可以使智能体编码基准（agentic coding benchmarks）的得分波动数个百分点——有时甚至超过排行榜上顶尖模型之间的差距。在这篇文章中，我们分享了关于基础设施如何影响基准得分的经验，以及社区可以采取的应对措施。

## 问题所在

公开基准通常旨在衡量纯粹的模型能力，但在实践中，它们有可能将模型能力与基础设施的特异性混为一谈。排行榜上2分的领先优势可能反映的是真正的能力差异，也可能只是因为某次评估在性能更强的硬件上运行，甚至可能只是运行时间碰巧更有利。

智能体评估（agentic evals）本质上是端到端的系统测试，该系统的任何组件都可能成为混淆因素。评估设置中的每一个要素都可能影响最终得分：集群健康状况、硬件规格、并发级别，甚至出口带宽。

## Terminal-Bench 2.0 案例研究

我们在 Google Kubernetes Engine（GKE）集群上运行 Terminal-Bench 2.0。在校准设置的过程中，我们注意到得分与该基准的官方排行榜不一致，而且基础设施错误率高得令人惊讶：**多达6%的任务因 pod 错误而失败**，其中大多数与模型解决任务的能力无关。

### 时间效应

我们通过观察发现，通过率会随一天中的不同时段而波动，这很可能是因为 API 延迟会随流量模式和突发事件而变化。这说明"模型能力"和"基础设施行为"之间的界限比单一基准分数所暗示的要模糊得多。

## 资源分配实验

我们系统性地改变了资源分配以衡量其影响：

### 1倍到3倍资源
在基准配置（1倍）和3倍资源之间，我们观察到基础设施错误显著下降。额外的资源主要解决了可靠性问题——在较低资源水平下会崩溃或超时的 pod，在有了更多余量后能够成功运行。

### 3倍到无上限资源
在3倍和无上限资源之间，基础设施错误又下降了**1.6个百分点**，而成功率则跃升了近**4个百分点**。额外的资源使智能体能够尝试只有在资源充足的情况下才可行的方法。

### 总体影响
在无上限资源下，相对于1倍配置的总提升为**+6个百分点**（p < 0.01）。这是一个显著的效应——比许多模型在智能体编码排行榜上的差距还要大。

### 两种不同的效应

在大约3倍 Terminal-Bench 规格以下，额外的资源解决的是基础设施可靠性问题。Terminal-Bench 维护者所使用的沙箱提供商在幕后隐式地做着同样的事情。然而，超过3倍的阈值后，额外的资源开始真正帮助智能体解决它之前无法解决的问题。

## 启示

### 对基准使用者而言
在没有公开或标准化的配置设置的情况下，外部观察者很难判断分数差异反映的是真正的能力差异还是仅仅是基础设施差异。在解读基准分数时应考虑到这一不确定性。

### 对基准创建者而言
基础设施配置应被视为一级实验变量（first-class experimental variable），以与提示词格式或采样温度（sampling temperature）同等的严谨程度进行记录和控制。

### 对实验室而言
智能体评估的资源配置应被视为一级实验变量，以与提示词格式或采样温度同等的严谨程度进行记录和控制。

## 建议

1. **记录基础设施信息**：在发布基准结果的同时，公开硬件规格、资源限制和集群配置
2. **进行多次试验**：报告置信区间，而非单点估计
3. **控制时间效应**：在固定时间运行评估，或在不同时间段进行随机化
4. **将基础设施故障与模型故障分开**：单独跟踪和报告 pod 错误、超时及其他基础设施问题
5. **标准化资源分配**：就热门基准的基准资源配置达成共识
