# 8. 评估体系（Evals）

> 学习目标：掌握智能体评估的核心方法论，理解"评估优先"原则，学会构建有效的评估集和持续迭代策略。
>
> 来源：Anthropic Engineering Blog, "Demystifying evals for AI agents"

## 8.1 评估优先：先建评估，再建智能体

Anthropic 提出了一个反直觉的原则：**在智能体具备完整能力之前就建立评估体系**。

```
传统做法（效果差）：
  构建智能体 → 手动测试 → 发现问题 → 修复 → 重复

推荐做法（效果好）：
  定义评估标准 → 构建评估集 → 开发智能体 → 运行评估 → 迭代改进
       │                                        │
       └──────── 评估驱动开发 (Eval-Driven) ──────┘
```

**为什么要先建评估**：
- 明确"成功"的定义，避免目标漂移
- 量化改进效果，而非依赖主观感受
- 防止回归 — 修复一个问题不会引入新问题
- 建立迭代的信心基线

## 8.2 构建评估集

### 起步：20-50 个任务

不要追求完美的评估集，而是从**真实失败案例**开始：

```
评估集来源：

1. 实际用户的失败案例        ← 最有价值
2. 边界条件和极端情况        ← 暴露脆弱性
3. 常见的典型任务            ← 基准参照
4. 之前手动测试发现的问题     ← 防止回归
```

**评估任务结构**：

```json
{
  "id": "eval_001",
  "description": "修复 React 组件中的 useEffect 依赖缺失警告",
  "input": {
    "user_message": "修复 src/components/Dashboard.tsx 中的 useEffect 依赖问题",
    "context_files": ["src/components/Dashboard.tsx"]
  },
  "success_criteria": {
    "must": [
      "ESLint react-hooks/exhaustive-deps 警告消除",
      "组件功能不变",
      "不引入无限渲染循环"
    ],
    "should": [
      "使用 useCallback 或 useMemo 优化",
      "添加必要的依赖项而非忽略警告"
    ],
    "must_not": [
      "添加 eslint-disable 注释",
      "删除 useEffect"
    ]
  }
}
```

### 迭代扩展

```
Phase 1: 20-50 个核心任务（覆盖主要场景）
    │
    ▼
Phase 2: 50-100 个任务（增加边界条件和复杂场景）
    │
    ▼
Phase 3: 100+ 个任务（覆盖长尾场景和回归防护）
```

## 8.3 评估方法论

### 核心原则：评判结果，不评判路径

```
❌ 错误做法：评判智能体使用了哪些工具、什么顺序
  "智能体应该先读文件，再搜索，再编辑"

✅ 正确做法：评判最终结果是否符合预期
  "代码能通过所有测试" / "回答包含了所有关键信息"
```

智能体可能用不同的路径达到相同的正确结果，限制路径会排除有效的解法。

### 四种评估方法

| 方法 | 描述 | 优势 | 劣势 |
|------|------|------|------|
| **确定性测试** | 代码测试、正则匹配、精确比对 | 快速、可靠、便宜 | 只能验证客观结果 |
| **LLM 评分** | 用另一个 LLM 评估输出质量 | 可评估主观质量 | 有评分偏差、成本高 |
| **人工评估** | 人类专家审查 | 最高质量判断 | 慢、贵、不可规模化 |
| **A/B 测试** | 比较两个版本的实际表现 | 反映真实用户体验 | 需要流量、周期长 |

### 组合策略

```
┌──────────────────────────────────────────────────┐
│              评估金字塔                            │
│                                                  │
│                   ┌───┐                          │
│                   │ 人 │  ← 少量高价值的人工评估    │
│                  ─┤ 工 ├─                        │
│                 ┌─┤ 评 ├─┐                       │
│                 │ │ 估 │ │                       │
│               ──┤ └───┘ ├──                      │
│              ┌──┤ LLM  ├──┐                      │
│              │  │ 评分  │  │  ← 中等数量的 LLM 评估 │
│            ──┤  └──────┘  ├──                     │
│           ┌──┤ 确定性测试  ├──┐                    │
│           │  │            │  │  ← 大量自动化测试    │
│           └──┴────────────┴──┘                    │
└──────────────────────────────────────────────────┘
```

### LLM 评分示例

```typescript
// 使用 LLM 作为评估者
async function llmGrader(task: string, output: string): Promise<{
  score: number;
  reasoning: string;
}> {
  const response = await client.messages.create({
    model: "claude-sonnet-4-6",
    max_tokens: 1024,
    system: `你是一个严格的评估者。根据评分标准对输出打分。
输出 JSON 格式：{ "score": 0-10, "reasoning": "评分理由" }`,
    messages: [{
      role: "user",
      content: `任务：${task}

智能体输出：
${output}

评分标准：
- 准确性 (0-3): 信息是否正确
- 完整性 (0-3): 是否覆盖所有要点
- 可操作性 (0-2): 建议是否具体可执行
- 格式 (0-2): 格式是否清晰易读`,
    }],
  });

  return JSON.parse(extractText(response));
}
```

## 8.4 持续评估与迭代

### 评估驱动开发循环

```
┌────────────────────────────────────────┐
│         评估驱动开发循环                 │
│                                        │
│   修改智能体  ──▶  运行评估集            │
│       ▲               │               │
│       │               ▼               │
│       │        分析结果变化              │
│       │               │               │
│       │       ┌───────┼───────┐        │
│       │       ▼       ▼       ▼        │
│       │    通过率   新失败   回归        │
│       │    提升?    案例?   问题?        │
│       │       │       │       │        │
│       └───────┴───────┴───────┘        │
└────────────────────────────────────────┘
```

### 关键指标

| 指标 | 说明 | 目标 |
|------|------|------|
| 通过率 (Pass Rate) | 评估集整体通过比例 | 持续上升 |
| 回归率 (Regression Rate) | 之前通过现在失败的比例 | 趋近 0% |
| 首次通过率 (First-pass Rate) | 不需重试即通过的比例 | 尽可能高 |
| 平均 Token 用量 | 完成任务的平均 Token 消耗 | 持续优化 |
| 平均步骤数 | 完成任务的平均工具调用次数 | 合理区间 |

### 生产环境监控

```
生产流量
    │
    ▼
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 用户反馈  │     │ 异常检测  │     │ 转录审查  │
│ 收集      │     │ 自动报警  │     │ 定期抽样  │
└────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │
     └────────────────┼────────────────┘
                      ▼
              ┌──────────────┐
              │ 补充到评估集  │
              └──────────────┘
```
