# 10. 长时运行智能体架构

> 学习目标：掌握长时运行智能体的架构模式，包括初始化-编码双智能体模式、进度追踪和会话管理。
>
> 来源：Anthropic Engineering Blog, "Effective harnesses for long-running agents"

## 10.1 长时运行的挑战

当智能体需要执行跨越数小时甚至数天的任务时，面临三大核心挑战：

```
挑战 1: 上下文窗口限制
  └── 对话历史超过 token 限制，丢失早期信息

挑战 2: 状态连续性
  └── 会话中断后需要恢复到之前的工作状态

挑战 3: 进度追踪
  └── 复杂任务需要知道哪些已完成、哪些待处理
```

## 10.2 初始化智能体 + 编码智能体双模式

Anthropic 提出的解决方案是将长时运行任务拆分为两个阶段的智能体：

```
┌────────────────────────────────────────────────────────┐
│               长时运行智能体架构                          │
│                                                        │
│   阶段一：初始化智能体（运行一次）                         │
│   ┌──────────────────────────────────────┐              │
│   │  1. 创建 Git 仓库                     │              │
│   │  2. 生成初始化脚本                     │              │
│   │  3. 创建功能清单 (feature-list.md)     │              │
│   │  4. 创建进度日志 (claude-progress.txt) │              │
│   └──────────────────────────────────────┘              │
│                         │                               │
│                         ▼                               │
│   阶段二：编码智能体（每个会话运行一次）                    │
│   ┌──────────────────────────────────────┐              │
│   │  1. 读取进度日志，了解当前状态          │              │
│   │  2. 从功能清单选择下一个任务            │              │
│   │  3. 实现一个功能                       │              │
│   │  4. 运行端到端测试                     │              │
│   │  5. 提交代码                          │              │
│   │  6. 更新进度日志                       │              │
│   └──────────────────────────────────────┘              │
│        │                                                │
│        └──── 重复，直到所有功能完成 ────────────────────── │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 初始化智能体的职责

```
输出制品：
  ├── init.sh              ← 环境搭建脚本
  ├── feature-list.md      ← 功能清单及优先级
  ├── claude-progress.txt  ← 进度追踪文件
  └── .git/                ← 版本控制
```

**`claude-progress.txt` 示例**：

```markdown
# 项目进度

## 已完成
- [x] 项目初始化和环境配置
- [x] 用户认证模块（注册、登录、JWT）
- [x] 数据库 schema 设计和迁移

## 进行中
- [ ] REST API 端点实现（80% 完成，缺少分页）

## 待开始
- [ ] 前端 UI 组件
- [ ] 集成测试
- [ ] 部署配置

## 已知问题
- 分页参数验证需要加强
- JWT 刷新逻辑待优化

## 上次会话备注
最后工作在 src/api/routes.ts 的 GET /users 端点。
分页逻辑需要处理 offset 超出总数的情况。
```

### 编码智能体的工作流

```typescript
// 编码智能体每次会话的流程
const codingAgentWorkflow = `
1. 读取 claude-progress.txt 了解项目状态
2. 运行 init.sh 确保环境就绪
3. 查看 feature-list.md 选择下一个优先任务
4. 实现该功能：
   a. 阅读相关代码
   b. 编写实现代码
   c. 编写测试
   d. 运行测试确保通过
5. git commit 提交更改
6. 更新 claude-progress.txt：
   - 标记已完成的任务
   - 记录当前状态和备注
   - 列出发现的新问题
`;
```

## 10.3 进度追踪制品

清晰的制品（artifacts）让智能体在**新的上下文窗口**中快速恢复状态：

### Git 历史作为进度记录

```
git log --oneline
  a1b2c3d  feat: add user pagination to GET /users
  d4e5f6g  feat: implement JWT authentication
  h7i8j9k  feat: add user registration endpoint
  l0m1n2o  chore: initial project setup
```

每次提交就是一个检查点，智能体可以通过 `git log` 和 `git diff` 了解已完成的工作。

### 结构化进度文件

```
文件系统中的状态制品：

project/
  ├── claude-progress.txt    ← 高层进度和备注
  ├── feature-list.md        ← 功能清单和优先级
  ├── CHANGELOG.md           ← 变更记录
  └── .claude/
      └── memory.md          ← 智能体持久化记忆
```

## 10.4 会话管理与上下文保持

### 上下文压缩策略

当对话接近 token 限制时，需要**压缩**历史消息：

```
原始对话（100K tokens）：
  ├── 消息 1-50:  早期探索和讨论
  ├── 消息 51-80: 实现细节
  └── 消息 81-100: 当前工作

压缩后（30K tokens）：
  ├── 摘要: "已完成用户认证模块，当前在实现 API 端点"
  ├── 关键决策: "选择 JWT 而非 Session 认证"
  └── 消息 81-100: 当前工作（完整保留）
```

### 会话恢复策略

```
会话恢复流程：

1. 读取 claude-progress.txt      ← 了解全局状态
2. 读取最近 5 次 git commit      ← 了解近期变更
3. 读取当前工作文件               ← 了解代码状态
4. 恢复工作上下文                 ← 继续上次的任务
```

### Claude Agent SDK 会话功能

```typescript
// 会话管理 — 保持跨交互的上下文
import { Session } from "@anthropic-ai/claude-agent-sdk";

// 创建新会话
const session = await Session.create({
  model: "claude-sonnet-4-6",
  tools: [...],
  systemPrompt: "...",
});

// 首次交互
const result1 = await session.send("实现用户注册功能");

// 后续交互（保持上下文）
const result2 = await session.send("现在添加登录功能");

// 保存会话 ID，下次恢复
const sessionId = session.id;

// 恢复会话
const resumed = await Session.resume(sessionId);
const result3 = await resumed.send("继续上次的工作");
```

## 10.5 检查点与错误恢复

```
┌─────────────────────────────────────────┐
│           检查点策略                      │
│                                         │
│   任务开始                               │
│       │                                 │
│       ▼                                 │
│   ┌──────────┐                          │
│   │ 检查点 1  │  ← git commit           │
│   │ 功能 A   │                          │
│   └────┬─────┘                          │
│        │                                │
│        ▼                                │
│   ┌──────────┐                          │
│   │ 检查点 2  │  ← git commit           │
│   │ 功能 B   │                          │
│   └────┬─────┘                          │
│        │                                │
│        ▼                                │
│   ┌──────────┐                          │
│   │ 错误!    │  ← 测试失败              │
│   └────┬─────┘                          │
│        │                                │
│        ▼                                │
│   回滚到检查点 2                         │
│   重新尝试或跳过当前任务                  │
│                                         │
└─────────────────────────────────────────┘
```

**关键洞察**：清晰的制品（progress 文件、git 历史）让智能体在全新的上下文窗口中也能快速理解项目状态，这是长时运行成功的基础。
