# 05 — 防范策略与最佳实践

> 学习目标：掌握个人和企业层面的 AI 安全防范策略，学会加固 AI 系统的安全性。

## 个人防护指南

### 安全意识核心原则

```
AI 时代的安全黄金法则：

1. 零信任原则 — 不要因为"看起来真实"就信任，音视频都可能伪造
2. 多渠道验证 — 重要事项必须通过不同渠道确认
3. 最小信息暴露 — 减少在网上公开的个人信息
4. 持续学习 — 了解最新的 AI 安全威胁和诈骗手法
```

### 防范 AI 诈骗

**通信安全：**

```
接到可疑电话/消息时：

步骤 1：暂停
  不要在情绪压力下做决定。
  "紧急"和"保密"是诈骗的经典信号。

步骤 2：验证
  挂断电话，通过已知的联系方式（不是对方提供的）主动联系。
  与家人设定"安全词"用于紧急验证。

步骤 3：核实
  涉及金钱、密码、个人信息的请求，一律当面或视频确认。
  要求对方做实时互动验证（如举手、特定手势）。

步骤 4：报告
  遭遇诈骗及时报警。
  告知亲友最新诈骗手法。
```

**账号安全：**

| 措施 | 做法 | 重要程度 |
|------|------|---------|
| 强密码 | 每个账号不同密码，使用密码管理器 | 必须 |
| 双因素认证（2FA） | 所有重要账号开启，优先使用认证器 App | 必须 |
| 定期检查 | 查看账号登录记录和授权的第三方应用 | 建议 |
| 密码泄露监控 | 使用 Have I Been Pwned 等服务监控 | 建议 |
| 恢复选项 | 确保账号恢复方式（邮箱/电话）安全有效 | 必须 |

**日常防护：**

- 不下载来源不明的 AI 工具、"破解版"软件
- 不在非官方 AI 平台输入敏感信息（身份证号、银行卡号）
- 谨慎授予 AI 应用的权限（摄像头、麦克风、通讯录、文件访问）
- 定期更新操作系统和应用程序
- 使用正规的杀毒软件并保持更新

### 保护个人隐私

```
信息分级保护：

极高敏感（绝不公开）：
  身份证号、银行卡号、密码、生物特征原始数据

高敏感（严格限制）：
  家庭住址、工作单位详情、个人行程、私密照片

中敏感（选择性公开）：
  手机号、邮箱、生日、教育经历

低敏感（可适度公开）：
  兴趣爱好、职业方向、公开作品
```

## 企业安全框架

### AI 安全治理架构

```
企业 AI 安全框架：

治理层：
├── AI 安全政策制定
├── AI 使用规范与审计
├── 安全责任与组织架构
└── 合规与法律要求

技术层：
├── AI 系统安全评估
├── 数据安全与隐私保护
├── 模型安全测试（红队测试）
├── 运行监控与异常检测
└── 事件响应与应急处理

人员层：
├── 员工 AI 安全培训
├── 安全意识教育
├── AI 使用行为规范
└── 定期安全演练
```

### 企业 AI 使用安全规范

**数据安全：**

```
在使用外部 AI 服务时：

✅ 允许：
- 使用公开信息进行查询
- 用脱敏后的数据进行分析
- 使用 AI 生成通用模板和文案

❌ 禁止：
- 上传客户个人信息到公共 AI 平台
- 输入公司商业机密、财务数据、源代码
- 使用 AI 处理未脱敏的敏感数据
- 将内部文档直接粘贴到 AI 对话中
```

**代码安全：**

```
使用 AI 辅助编程时：

1. 代码审查
   AI 生成的代码必须经过人工安全审查
   重点关注：输入验证、权限检查、数据处理

2. 依赖管理
   AI 推荐的第三方库必须验证来源和安全性
   使用 npm audit / pip audit 等工具扫描依赖

3. 密钥保护
   禁止在 AI 对话中分享 API 密钥或凭证
   AI 生成的配置文件注意检查是否包含硬编码密钥

4. 安全测试
   AI 生成的代码需要进行安全测试
   使用 SAST/DAST 工具自动化扫描
```

### 企业防御 AI 攻击

**防范 AI 钓鱼：**

- 部署 AI 驱动的邮件安全网关（用 AI 对抗 AI）
- 定期进行钓鱼模拟演练
- 建立可疑邮件举报机制
- 关键操作（大额转账、权限变更）需要多人审批

**防范深度伪造：**

- 视频会议中的重要指令需要后续书面确认
- 建立内部身份验证机制（不依赖音视频）
- 培训员工识别深度伪造的能力
- 对外公开的高管音视频素材进行管控

## AI 系统安全加固

### 大语言模型（LLM）应用安全

```
LLM 应用安全清单：

输入安全：
- [ ] 实施提示注入防护（输入过滤、指令隔离）
- [ ] 限制用户输入长度和格式
- [ ] 对用户输入进行清理和转义

输出安全：
- [ ] 不要信任 AI 输出——验证后再使用
- [ ] 限制 AI 可以执行的操作范围
- [ ] 对 AI 输出进行内容审核（过滤敏感信息）
- [ ] 输出中不包含系统提示词或内部信息

权限控制：
- [ ] AI 应用遵循最小权限原则
- [ ] AI 不直接访问数据库——通过受控 API 层
- [ ] 敏感操作需要用户二次确认
- [ ] 实施速率限制防止滥用

数据保护：
- [ ] 用户对话数据加密存储
- [ ] 明确数据保留策略和删除机制
- [ ] 不将用户数据用于模型训练（除非明确授权）
- [ ] 日志中不记录敏感信息
```

### 模型安全

```
模型安全最佳实践：

部署前：
- 只使用来源可信的模型
- 验证模型文件的完整性（哈希校验）
- 在隔离环境中测试模型行为
- 进行红队测试（模拟攻击场景）

运行时：
- 监控模型输出的异常模式
- 实施输入输出日志审计
- 设置模型行为基线，检测偏离
- 定期评估模型性能变化

更新时：
- 模型更新前在测试环境验证
- 保留模型版本回滚能力
- 更新后进行安全回归测试
```

### 防范提示注入

```typescript
// 防范提示注入的关键策略

// 1. 系统提示与用户输入分离
const systemPrompt = "你是一个客服助手，只回答产品相关问题。";
const userInput = sanitize(rawInput); // 清理用户输入

// 2. 输入验证和过滤
function sanitize(input: string): string {
  // 移除可能的注入尝试
  const maxLength = 2000;
  let cleaned = input.slice(0, maxLength);
  // 检测常见注入模式
  const suspiciousPatterns = [
    /忽略.*指令/i,
    /ignore.*instructions/i,
    /system.*prompt/i,
    /你的.*角色/i,
  ];
  for (const pattern of suspiciousPatterns) {
    if (pattern.test(cleaned)) {
      // 记录日志并标记
      logSuspiciousInput(cleaned);
    }
  }
  return cleaned;
}

// 3. 输出过滤
function filterOutput(response: string): string {
  // 确保不泄露系统提示词
  // 确保不包含敏感信息
  // 确保格式符合预期
  return response;
}

// 4. 权限隔离
// AI 不直接执行系统命令
// AI 通过受限 API 访问数据
// 敏感操作需要人工确认
```

## 安全工具推荐

| 类别 | 工具 | 用途 |
|------|------|------|
| 密码管理 | Bitwarden, 1Password | 生成和管理强密码 |
| 双因素认证 | Google Authenticator, Authy | 账号二次验证 |
| 深度伪造检测 | Microsoft Video Authenticator | 检测伪造视频 |
| AI 文本检测 | GPTZero, Originality.ai | 检测 AI 生成文本 |
| 依赖安全 | Snyk, npm audit | 检测依赖库漏洞 |
| 代码安全 | SonarQube, Semgrep | 静态代码安全扫描 |
| 网络监控 | Wireshark, Pi-hole | 监控异常网络流量 |
| 隐私保护 | Firefox + uBlock Origin | 减少追踪和指纹识别 |

## 小结

- **个人防护**的核心：零信任、多渠道验证、最小信息暴露
- **企业安全**需要治理、技术、人员三层框架协同
- **AI 系统加固**重点关注输入安全、输出过滤、权限控制、数据保护
- **防范提示注入**是 LLM 应用安全的首要任务
- 安全是持续过程——定期培训、演练、更新防护措施
