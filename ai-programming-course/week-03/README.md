# Week 3 — 软件工程：人、月、代码组织工程

> 目标：理解软件工程不只是写代码，更是关于人的协作、时间的管理和代码的组织。从「能写代码」进阶到「能做工程」。

## 为什么需要学这些

你已经能用 AI 写代码、部署应用了。但当项目变大、团队变多时，你会遇到全新的挑战：

- **代码写了一个月，突然发现方向错了** → 需要更好的需求分析和规划
- **三个人同时改一个文件，冲突不断** → 需要合理的代码组织和协作规范
- **加了一个人，项目反而更慢了** → 这就是《人月神话》描述的经典问题
- **代码越写越乱，改一个 bug 冒出三个新 bug** → 需要架构设计和重构能力

## 学完本周你能做到

- 理解为什么「加人 ≠ 加速」，合理规划团队和时间
- 用 MVP 思维做需求分析，避免过度设计
- 设计清晰的项目结构，让代码易于理解和维护
- 掌握抽象、分层、分治等核心编程思想
- 识别代码坏味道，知道何时以及如何重构
- 建立团队协作的工程规范
- 理解技术债务，在速度和质量之间做平衡
- 在 AI 时代重新思考软件工程的最佳实践
