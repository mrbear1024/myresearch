# 08 — AI 时代的软件工程

> 学习目标：理解 AI 如何改变软件开发流程，掌握 AI 时代的最佳实践。

## 软件工程正在被重新定义

传统软件工程的核心流程是：需求 → 设计 → 编码 → 测试 → 部署。AI 不是替代了这个流程，而是改变了每个环节的「做法」。

| 环节 | 传统做法 | AI 时代做法 |
|------|---------|------------|
| 需求分析 | 人工分析、写文档 | AI 辅助拆解需求、生成用户故事 |
| 设计 | 白板画架构图 | AI 建议架构方案、生成技术选型对比 |
| 编码 | 人手写每一行 | AI 生成代码，人审查和调整 |
| 测试 | 人写测试用例 | AI 生成测试、自动补全边界情况 |
| 调试 | 看日志、加断点 | 把错误信息给 AI，AI 定位问题 |
| 部署 | 手动配置 CI/CD | AI 生成部署配置和脚本 |

## 新的最佳实践

### 1. 上下文工程（Context Engineering）

AI 的输出质量取决于你给它的上下文。管理上下文是 AI 时代最重要的技能。

```
项目级上下文：
├── CLAUDE.md          # 项目规则和约定
├── README.md          # 项目说明
├── .env.example       # 环境变量说明
└── 有意义的目录结构     # AI 能自动理解项目组织

请求级上下文：
- 完整的错误信息
- 相关的代码文件
- 期望的行为 vs 实际行为
- 技术栈和约束条件
```

### 2. AI 友好的代码

写代码时，除了考虑人能不能读懂，还要考虑 AI 能不能理解：

```typescript
// ❌ AI 难以理解的代码
const x = a ? (b > c ? d : e) : f;
const arr = data.map(i => i.v).filter(Boolean).reduce((a, b) => a + b, 0);

// ✅ AI 友好的代码
const isEligible = user.isActive && user.hasSubscription;
const activeUsers = users.filter(user => user.isActive);
const totalRevenue = activeUsers.reduce((sum, user) => sum + user.revenue, 0);
```

关键：**有意义的命名** + **清晰的结构** + **类型注解**。这些对人和 AI 都有帮助。

### 3. 人审查，AI 编写

在 AI 时代，开发者的角色更像「审查者」而不是「编写者」：

```
传统模式：人写代码 → 人 Review
AI 模式：AI 写代码 → 人 Review → AI 根据反馈修改 → 人确认
```

你需要培养的核心能力：
- **快速阅读代码**：看 AI 生成的代码是否正确
- **发现隐藏问题**：安全漏洞、性能问题、边界情况
- **判断方向**：AI 可能写出正确但不合适的代码

### 4. 测试驱动的 AI 开发

测试在 AI 时代变得更重要，因为 AI 生成的代码需要验证：

```bash
# 1. 先写（或让 AI 写）测试
claude "为 src/lib/chat.ts 的 sendMessage 函数写单元测试"

# 2. 让 AI 实现功能
claude "实现 sendMessage 函数，确保通过已有的测试"

# 3. 运行测试验证
npm test
```

## 不会被 AI 替代的能力

1. **需求理解**：AI 不知道用户真正需要什么
2. **架构决策**：在多种方案中做权衡
3. **产品判断**：决定做什么和不做什么
4. **沟通协调**：团队之间的信息同步
5. **学习能力**：持续适应新工具和新方法

## AI 时代的软件工程师画像

```
传统工程师：
  编码能力 ████████████████████ 80%
  系统设计 ████████             30%
  沟通协作 ████                 15%

AI 时代工程师：
  产品思维 ████████████         45%
  系统设计 ████████████         45%
  AI 协作  ████████████████     60%
  编码能力 ████████             30%（AI 承担了大部分）
  沟通协作 ████████████         45%
```

关键转变：从「写代码的人」变成「用 AI 构建产品的人」。

## 关键收获

1. **上下文工程**：CLAUDE.md、好的命名、清晰的结构是 AI 时代的基础设施
2. **人审查 AI 编写**：培养审查代码的能力比写代码更重要
3. **AI 友好的代码**：有意义的命名和类型注解帮助人和 AI 理解
4. **测试更重要了**：AI 生成的代码需要测试来验证
5. **核心是判断力**：知道做什么比知道怎么做更重要
