# 01 — AI 编程的工作原理

> 学习目标：建立对 AI 编程工具的正确心智模型，知道它能做什么、不能做什么。

## AI 是怎么写代码的

AI 编程工具（如 ChatGPT、Claude、Copilot）的底层都是大语言模型（LLM）。它们的工作方式：

1. **训练阶段**：阅读了互联网上海量的代码和文档
2. **推理阶段**：根据你的提示，预测"接下来最可能出现的文字/代码"

关键理解：**AI 不是在"思考"如何编程，而是在做极其高级的模式匹配。**

## AI 的能力圈

### AI 很擅长的事情

- **生成样板代码** — React 组件、API 路由、CRUD 操作
- **常见模式** — 表单验证、数据获取、列表渲染
- **代码解释** — 把复杂代码翻译成通俗语言
- **语法转换** — 不同语言/框架之间的代码翻译
- **修复常见错误** — 语法错误、类型错误、常见 bug
- **写文档和注释** — 根据代码生成说明

### AI 不太擅长的事情

- **复杂业务逻辑** — 涉及多个条件和状态的复杂流程
- **性能优化** — 可能给出理论上正确但实际低效的方案
- **安全性** — 可能生成有安全漏洞的代码
- **最新 API** — 训练数据有滞后，新发布的库/API 可能不准确
- **大型架构设计** — 看不到全局，容易过度设计或设计不足
- **调试隐蔽 bug** — 逻辑上微妙的错误很难发现

### AI 绝对做不到的事情

- 替你做决策（选什么技术、做什么产品）
- 保证代码 100% 没有 bug
- 理解你没说出来的需求
- 自动适应你项目中的独特约定

## 正确的心态

把 AI 想象成一个**经验丰富但不了解你项目的外包开发者**：

- 他写代码很快，但你需要清楚地告诉他要什么
- 他的代码可能看起来对，但你需要验证
- 他不会主动问你不明确的地方
- 你是项目负责人，他是执行者

## 实际例子

### 好的使用方式

```
你："用 Next.js App Router 创建一个 /api/users 的 GET 路由，
     从 Supabase 获取所有用户数据并返回 JSON。"

→ AI 可以准确生成，因为这是标准模式。
```

### 需要谨慎的使用方式

```
你："帮我优化数据库查询性能。"

→ 太模糊了。AI 可能给出通用建议，但不了解你的具体数据量、
   查询模式和性能瓶颈。
```

### 更好的方式

```
你："这个 SQL 查询在有 10 万条记录时很慢（3 秒），
     请帮我分析原因并优化：[粘贴 SQL]
     表结构如下：[粘贴建表语句]"

→ 给了足够的上下文，AI 可以给出有针对性的建议。
```

## 小结

- AI 是强大的编程辅助工具，不是全自动编程机
- 理解它的能力边界，才能更好地利用它
- 你的角色是**产品经理 + 代码审查者**，AI 的角色是**快速执行者**
- 随着你编程知识的增长，你驾驭 AI 的能力也会越来越强
