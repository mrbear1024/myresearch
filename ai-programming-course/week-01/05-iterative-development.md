# 05 — 与 AI 迭代开发

> 学习目标：掌握与 AI 协作进行迭代开发的工作流程，高效构建软件功能。

## 什么是迭代开发

不要试图一次写完所有代码。正确的方式：

```
小功能 → 测试 → 提交 → 下一个小功能 → 测试 → 提交 → ...
```

每次迭代都产出一个**可工作的版本**。

## 迭代开发工作流

### 第一步：拆解需求

拿到一个大功能时，先拆成小任务。

**例子：给聊天应用加用户认证功能**

```
大任务：用户认证
├── 1. 注册页面（UI）
├── 2. 登录页面（UI）
├── 3. Supabase Auth 集成
├── 4. 登录状态管理
├── 5. 保护需要登录的页面
└── 6. 退出登录功能
```

你可以让 AI 帮你拆：

> "我要给我的 Next.js 聊天应用加用户认证功能，使用 Supabase Auth。请帮我把这个功能拆分成可以逐步实现的小任务，按依赖关系排序。"

### 第二步：逐个实现

一次只做一个小任务：

```
你："先实现第 1 步：创建注册页面。使用 Next.js App Router，
     路由为 /auth/signup，包含邮箱和密码输入框，
     使用 Tailwind CSS 做样式。暂时不需要接入后端。"
```

AI 生成代码后：
1. 阅读代码，确认理解
2. 粘贴到项目中
3. 运行测试
4. Git 提交

### 第三步：持续推进

完成一个任务后，带着上下文继续：

```
你："注册页面已经完成并测试通过。现在实现第 3 步：
     接入 Supabase Auth。这是注册页面的代码：[粘贴]
     请帮我添加调用 supabase.auth.signUp 的逻辑。"
```

### 第四步：处理问题

遇到问题时，不要慌：

```
你："接入 Supabase Auth 后，注册时报错：
     'AuthApiError: User already registered'
     但这是一个新邮箱。我的代码如下：[粘贴]
     Supabase 项目配置中邮箱确认是开启状态。"
```

## 版本控制节奏

```bash
# 完成注册页面 UI
git add .
git commit -m "添加注册页面 UI"

# 完成登录页面 UI
git add .
git commit -m "添加登录页面 UI"

# 接入 Supabase Auth
git add .
git commit -m "集成 Supabase Auth 认证"

# 添加登录状态管理
git add .
git commit -m "添加登录状态管理和保护路由"
```

每个 commit 都应该是一个**可工作的状态**。如果改坏了，可以回退到上一个 commit。

## 与 AI 协作的最佳实践

### 保持对话连续性

在同一个对话中继续，AI 会记住之前的上下文：

```
第 1 条："帮我创建注册页面"
第 2 条："很好，现在加上表单验证"
第 3 条："接下来接入 Supabase Auth"
```

### 给 AI 看你的代码

当跨对话或上下文丢失时：

```
"这是我当前的项目结构和关键文件：
- app/auth/signup/page.tsx：[粘贴]
- lib/supabase.ts：[粘贴]

请帮我实现登录页面，风格和注册页面保持一致。"
```

### 先让 AI 分析再写代码

```
"我想给聊天应用加上对话历史侧边栏。
在写代码之前，请先分析：
1. 需要修改哪些文件
2. 数据流是怎样的
3. 有哪些需要注意的点"
```

## 实战练习：给聊天应用添加功能

选择一个功能来练习迭代开发：

1. **对话历史侧边栏** — 显示所有历史对话，点击切换
2. **Markdown 渲染** — AI 回复支持 Markdown 格式显示
3. **深色模式** — 添加深色/浅色主题切换
4. **消息搜索** — 搜索历史聊天记录

用上面学到的方法：拆解 → 逐步实现 → 每步测试并提交。

## 小结

- **大任务拆小** — 每次只做一个可测试的小功能
- **每步都提交** — Git commit 是你的安全网
- **持续给上下文** — AI 需要知道你的代码现状
- **遇到问题不要重来** — 把错误信息给 AI，让它帮你修
- 迭代开发不是 AI 编程专有的，它是所有软件开发的核心方法
